# AI와 확장팩 제작기 연결하기

MCP를 지원하는 AI 앱이 **현재 켜 놓은 확장팩 제작기**의 내용을 읽고 수정할 수 있습니다. 예를 들어 “원작 캐릭터를 검색해서 새 캐릭터로 추가하고, HP만 바꾼 뒤 검사해 줘”라고 요청할 수 있습니다. 캐릭터·스킬·맵·스토리 정의를 다루며, 원작 파일이나 게임 엔진 코드를 수정하는 기능은 없습니다.

## 처음 연결할 때

1. 게임 연결 화면에서 **확장팩 만들기**를 엽니다.
2. 작업할 프로젝트를 새 폴더에 저장합니다. 원작 게임 폴더와 캐시 폴더 밖이어야 합니다.
3. 제작기의 MCP 연결을 켜고 **MCP 설정 복사**를 누릅니다.
4. 사용할 AI 앱의 **로컬 MCP 서버 설정**에 복사한 설정을 넣습니다. 앱마다 설정 화면의 이름은 다릅니다.
5. 제작기를 켜 둔 채 AI 앱에서 연결을 시작합니다.

복사한 설정은 같은 컴퓨터의 제작기에 연결합니다. 배포판에 들어 있는 변환기를 서버로 실행하므로 Python을 별도로 설치할 필요가 없습니다. 개발 소스를 직접 실행할 때만 아래 Python 방법을 사용합니다.

처음에는 이렇게 요청해 보세요.

> 현재 프로젝트에 어떤 캐릭터가 있는지 알려 줘. 정품 원본 목록에서 원하는 캐릭터를 찾아 새 항목으로 추가하고, HP를 80으로 바꿔 줘. 바뀐 필드를 보여 준 뒤 검사해 줘.

> 방금 만든 캐릭터의 HP만 원본으로 초기화해 줘. 다른 설정과 내가 정한 레벨은 유지해 줘.

> 프로젝트를 저장하고, 공유용 ZIP을 이 프로젝트 폴더 안에 만들어 줘.

실제 게임으로 테스트하려면 정품 데이터가 준비되어 있어야 합니다. AI의 테스트 요청은 제작기의 **저장하고 테스트** 동작으로 이어집니다. 미리보기는 별도 게임 프로세스에서 실행되어 제작기와 MCP 연결을 유지합니다. AI는 실행 로그를 읽고 미리보기만 종료한 뒤 프로젝트 수정을 계속할 수 있습니다. 실행 도구의 성공은 게임 프로세스를 시작했다는 뜻이며, 전투 성공이나 전체 게임 검증을 뜻하지 않습니다.

이렇게 이어서 요청할 수 있습니다.

> 저장하고 테스트를 실행해 줘. 디버그 로그에서 오류를 확인한 다음 미리보기만 종료하고, 제작기에서 수정을 계속해 줘.

## 작업 폴더와 연결 끄기

연결을 켠 시점에 열려 있던 프로젝트 폴더가 MCP의 작업 범위가 됩니다. AI는 그 폴더 안에서 프로젝트를 저장하고 열거나 ZIP을 내보낼 수 있습니다. 프로젝트를 아직 저장하지 않았다면 앱의 개인 데이터 폴더 안 `mcp_projects`를 사용합니다. 다른 위치의 프로젝트를 작업하려면 연결을 끄고, 제작기에서 해당 프로젝트를 연 뒤 다시 켜세요.

연결을 끄거나 제작기를 닫으면 로컬 서버가 종료됩니다. 개인 연결 파일에는 임시 인증값이 들어 있으므로 GitHub에 올리거나 다른 사람에게 보내지 마세요. 복사하는 MCP 클라이언트 설정에는 인증값을 직접 넣지 않고 그 파일의 경로를 사용합니다. 실제 AI 제공업체로 전달되는 프로젝트 내용은 사용하는 AI 앱의 설정을 따릅니다.

## 사용할 수 있는 도구

| 도구 | 하는 일 |
| --- | --- |
| `ft2_read_project` | 현재 프로젝트와 원본 연결 상태 보기 |
| `ft2_list_originals` | 개인 정품 캐시의 원본 캐릭터·스킬 검색 |
| `ft2_get_record` | 항목 하나와 원본 대비 변경 필드 보기 |
| `ft2_create_record` | 새 항목 만들기, 원본 캐릭터·스킬을 기반으로 만들기 |
| `ft2_update_record` | 항목의 일부 필드 바꾸기 |
| `ft2_reset_field` | 선택한 원본 필드 하나 초기화 |
| `ft2_reset_record` | 항목의 원본 필드 전체 초기화 |
| `ft2_validate` | 프로젝트 형식·참조 검사 |
| `ft2_save` | 작업 범위 안에 정의 파일 저장 |
| `ft2_open` | 작업 범위 안의 프로젝트 열기 |
| `ft2_export` | 정의 파일만 든 공유용 ZIP 만들기 |
| `ft2_play` | 저장 후 게임 테스트 요청 |
| `ft2_get_debug_output` | 미리보기 상태와 최근 실행 로그 확인 |
| `ft2_stop_play` | 이 제작기가 실행한 미리보기만 종료 |

`kind`는 `characters`, `skills`, `maps`, `stories` 중 하나입니다. `index`는 현재 프로젝트 목록에서 0부터 시작하는 위치입니다. `original_id`는 검색 결과에 나오는 정품 원본 번호입니다. 원본 검색과 원본 초기화는 정품 데이터가 연결되어 있어야 가능합니다.

MCP 도구는 총 14개입니다. `ft2_play`는 프로세스 시작 결과를 반환하고, `ft2_get_debug_output`은 `running`, `pid`, `log_tail`, `error`를 제공합니다. `ft2_stop_play`는 제작기가 직접 실행해 관리 중인 미리보기만 종료합니다. 일반 게임 프로세스나 다른 앱을 종료하는 기능은 없습니다. 미리보기 API를 제공하지 않는 테스트 호스트에서는 실행 요청만 전달하며, 로그·정지 도구는 지원하지 않는다는 오류를 반환합니다.

캐릭터 능력치 변경 예: `{"kind":"characters","index":0,"patch":{"stats":{"hp.initial":80}}}`. 해당 능력치 초기화 예: `{"kind":"characters","index":0,"key":"hp.initial"}`. 초기화는 원본 참조와 로컬 항목 ID, 사용자가 정한 레벨을 유지합니다. 직업 표에 존재하지 않는 레벨과, 같은 번호 APD 파일로 추론한 외형은 원본 수치와 구분됩니다.

## 개발자가 Python으로 직접 실행하기

Python 3.10 이상과 표준 라이브러리만 사용합니다. 별도 패키지나 AI API 키는 필요하지 않습니다.

```sh
python tools/editor_mcp.py --connection "제작기에 표시된 개인 연결 파일 경로"
```

위 명령은 MCP 클라이언트가 자식 프로세스로 실행하는 명령입니다. 일반 터미널에서 실행하면 JSON 요청을 기다립니다. stdout에는 MCP JSON-RPC 메시지만 출력합니다.

클라이언트 설정의 기본 모양은 다음과 같습니다. 실제 `command`와 절대 경로는 제작기의 복사 기능을 사용하세요.

```json
{
  "mcpServers": {
    "ft2-editor": {
      "command": "python",
      "args": ["/absolute/path/tools/editor_mcp.py", "--connection", "/absolute/path/editor_mcp_connection.json"]
    }
  }
}
```

표준 stdio의 `initialize` → `notifications/initialized` → `tools/list` / `tools/call` 순서를 지원합니다. 지원 revision은 `2025-11-25`, `2025-06-18`, `2025-03-26`, `2024-11-05`입니다. 클라이언트가 다른 revision을 제안하면 `2025-11-25`를 응답하며, 클라이언트는 그 버전을 지원하는지 확인해야 합니다. 2026 이후의 별도 lifecycle을 구현했다고 주장하지 않습니다. [공식 lifecycle 규격](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle), [공식 stdio 규격](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports), [공식 tools 규격](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)을 기준으로 구현했습니다.

Godot 쪽 연결은 외부에 노출하지 않는 별도 로컬 통신입니다. `127.0.0.1`만 수신하며, 시작할 때 만든 임의 인증값을 확인합니다. 요청과 응답은 각각 1 MiB 이하이며, 불완전한 요청은 5초 후 닫습니다. macOS·Linux의 연결 파일은 사용자만 읽고 쓰는 `0600` 권한입니다. 셸 실행, 임의 GDScript 평가, 원작·캐시 쓰기, 작업 범위 밖 파일 쓰기를 제공하지 않습니다. ZIP에는 기존 제작기와 동일하게 작성한 `mod.json`, `content.json`만 포함됩니다.

회귀 검사:

```sh
python -m unittest discover -s tools/tests -p test_editor_mcp.py -v
```

`FT2_BRIDGE_GODOT` 환경변수에 Godot 실행파일 경로를 지정하면 합성 데이터로 실제 Godot TCP 연결, stdio 호출, 원본 초기화와 폴더 보호까지 검사합니다. 원작 데이터를 넣지 않습니다.
