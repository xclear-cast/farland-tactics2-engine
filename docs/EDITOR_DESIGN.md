# 확장팩 제작기 작업 화면 설계

파랜드 택틱스 2의 정품 자료를 로컬에서 참고하며 캐릭터·스킬·맵·스토리를 만드는 제작기입니다. 사용자가 요청한 EUD/StarForge 계열의 목록 중심 작업 흐름을 참고해, 선택한 대상과 수정할 속성을 같은 화면에서 연결합니다. 해당 제품의 코드·화면 자산을 가져오거나 포맷 호환을 구현하는 작업은 아닙니다.

## 참고한 편집기 패턴

| 공식 자료 | 이 제작기에 적용하는 원칙 |
| --- | --- |
| [Unity Inspector: Inspect items](https://docs.unity.com/en-us/engine/6000.7/manual/unity-editor/editor-windows-views-reference/using-the-inspector/inspector-items) | 선택한 항목의 종류에 따라 속성 편집 내용을 바꿉니다. 캐릭터·스킬·맵·스토리를 고르면 해당 폼이 나타납니다. |
| [Unreal Engine: Details Panel](https://dev.epicgames.com/documentation/unreal-engine/level-editor-details-panel-in-unreal-engine?lang=en-US) | 목록 검색과 속성 편집을 연결하고, 기준값에서 달라진 항목을 표시하며 되돌리기 동작을 제공합니다. |
| [Tiled: Introduction](https://docs.mapeditor.org/en/stable/manual/introduction/) | 맵은 실제 위치를 보며 선택·그리기하고, 지형과 배치를 구분합니다. 프로젝트 자료를 작업 목록에서 찾을 수 있게 합니다. |

이는 설계 판단의 근거입니다. 세 편집기의 전체 기능을 제공한다는 뜻은 아닙니다.

## 값의 출처와 되돌리기

- **정품 원본 목록**: 연결한 개인 캐시의 원본 테이블을 읽습니다. 원작 캐릭터·스킬을 선택해 확장팩의 새 항목으로 가져옵니다.
- **기준값과 변경값**: 캐릭터 수치의 변경 설정을 지우면 선택한 원작 직업의 값을 상속합니다. 스킬 초기화는 선택한 원작 스킬의 편집 가능한 값을 복원합니다. 새 항목의 ID는 유지합니다.
- **개별 초기화와 전체 초기화**: 한 수치만 되돌리거나 해당 캐릭터·스킬의 편집 값을 전체 복원합니다. 캐릭터 레벨은 배치·제작 설정이므로 원작 직업 테이블의 기본값이라고 표시하지 않습니다. 스프라이트 후보도 테이블 값과 구분합니다.
- **맵·스토리**: 제작한 격자·배치와 선언형 노드를 편집합니다. 이 둘은 원작 캐릭터·스킬의 기본값 복원과 같은 기능으로 취급하지 않습니다.

저장·내보내기는 확장팩 정의를 기록합니다. 정품 폴더와 개인 콘텐츠 캐시는 편집 대상이 아닙니다. 새 맵의 타일과 캐릭터·스킬 연출은 각 사용자의 정품 자료를 참조합니다. PNG/APD 가져오기, 원작 챕터 진행 중 확장 스토리 진입·복귀는 현재 지원 범위에 포함되지 않습니다.

## 검증 범위

`game/tests/test_extension_editor.gd`는 자체 자료로 기본 폼·저장·내보내기를 검사하고, `test_expansion_workflow.gd`는 개인 정품을 연결해 제작기 → 설정 화면 → 확장 스토리 실행을 검사합니다.

`test_editor_workbench.gd`는 별도로 지정한 로컬 정품·캐시에서 고렘 계열을 포함한 여러 캐릭터와 여러 스킬의 값을 읽고, 실제 폼의 수정·초기화·저장·재열기를 비교합니다. 원작 수치를 공개 테스트에 복사하지 않으며, 실행 전후 정품·캐시의 모든 파일 SHA256을 비교합니다. 검증 산출물은 지정한 비공개 폴더에만 기록합니다. 기본 검사는 화면을 캡처하지 않으며, 별도 요청으로 생성하는 격리 창의 검토용 캡처도 공개 자료에 포함하지 않습니다. 합성 자료 검사만으로 실제 정품 동작이 검증되었다고 판정하지 않습니다.

WSL에서 대량 파일 해시가 느릴 때는 `--skip-fingerprint`로 GPU 화면 검사만 분리할 수 있습니다. 이때 테스트 결과의 파일 불변 판정은 미검증으로 남습니다. 별도 네이티브 파일 검사로 정품·캐시 전체의 실행 전후 해시가 같음을 확인해야 전체 검증이 완료됩니다.

`test_editor_preview.gd`는 비공개 로컬 프로젝트와 연결 파일을 지정해 실제 MCP 클라이언트가 접속할 테스트 호스트를 엽니다. 별도 stdio 클라이언트로 14개 도구, 테스트 게임의 별도 프로세스 시작·실제 로그·중지, 중지 후 추가 편집·초기화·저장을 확인합니다. 클라이언트별 설정의 JSON/TOML 문법 검사와 실제 MCP 프로토콜 연결을 구분하며, 외부 AI 서비스나 특정 상용 클라이언트 전체를 검증했다고 주장하지 않습니다.
