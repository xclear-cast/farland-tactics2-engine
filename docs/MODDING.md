# 모드 제작 시작하기

이 문서와 직접 만든 예제 모드는 [예제 MIT 라이선스](../EXAMPLES_LICENSE)에 따라
복사·수정해서 사용할 수 있습니다. 원작 자료의 권리까지 주는 라이선스는 아닙니다.

목표는 사람들이 이 도구로 **파랜드 택틱스 2의 확장팩을 제작·실행·공유**하는 것입니다.
정품 게임을 바탕으로 원작 자원을 로컬에서 활용하고, 자신의 스토리·맵·캐릭터·스킬을
추가하는 확장팩 제작 도구를 지향합니다.

이 문서는 그 기반인 **우리 엔진의 현재 모드 규격**입니다. 아이템 가격 같은 변경은 원작 EXE나
DAT의 바이트 구조를 몰라도 만들 수 있습니다. 원작 데이터가 필요한 부분은 각 사용자의
정품 폴더에서 변환하며, 모드에는 자신이 작성한 변경 지시와 새 자료만 넣습니다.

**0.2.0-preview의 schema 2는 새 캐릭터·스킬 정의·격자 맵·스토리 에피소드와 제작 GUI를
제공합니다.** 화면에서 만들려면 [제작기 사용법](EXPANSION_EDITOR.md)부터 보세요.
[`example_expansion`](../mods/example_expansion/)은 이 기능을 묶은 자체 예제입니다.

아래의 작은 `schema: 1` 예제는 기존 수치 수정·파일 교체 방식을 그대로 설명합니다.
현재 앱은 정품 설치 폴더와 개인 캐시 연결을 전제로 하며, 모든 스킬 동작이나 자작
그래픽 가져오기를 자유롭게 구현하는 범용 편집기까지 완성된 것은 아닙니다.

## 어떤 것을 고치는 작업인가요?

| 하고 싶은 일 | 작업할 곳 |
| --- | --- |
| 기존 포팅의 이동·전투·UI·게임 규칙을 수정 | `game/scripts/` 엔진 코드 |
| 원작 파일을 잘못 읽거나 이미지/이벤트 변환이 틀리는 문제 수정 | `tools/converters/` 변환기 코드 |
| 엔진 수정 없이 아이템 가격·기존 스킬 MP 등을 변경 | 별도 `mods/내_모드/` |
| 새 캐릭터·스킬·전장·스토리 에피소드 제작 | **확장팩 만들기** GUI의 schema 2 정의 프로젝트 |
| 기존 자료의 파일 교체나 전문적인 데이터 연결 | 모드의 `files/`와 관련 인덱스/JSON 패치. 엔진의 지원 범위 확인 |
| 자작 PNG/APD 가져오기, 새 스킬 처리·새 VM 명령 추가 | 현재 제작기 미지원. 별도 엔진/변환기 확장 필요 |

원작에 가깝게 포팅을 고치는 작업과 새로운 커스텀을 만드는 작업을 분리하면,
원작 데이터나 공통 엔진을 직접 덮어쓰지 않고 변경을 켜고 끌 수 있습니다.

## 1. 가장 작은 모드 만들기

별도 폴더를 만들고, 그 안에 UTF-8 텍스트 파일 `mod.json`을 저장합니다.
Windows 메모장을 사용한다면 파일 이름이 `mod.json.txt`가 되지 않았는지 확인하세요.

```text
내 모드/
└─ mod.json
```

다음 내용은 **기존 1번 아이템의 가격만 10으로 바꾸는 자체 설정 예제**입니다.
원작 이름·이미지·테이블 레코드를 복사할 필요가 없습니다.

```json
{
  "schema": 1,
  "id": "my_item_price",
  "name": "내 가격 조정",
  "version": "1.0",
  "table_edits": [
    {"table": "item", "record": 1, "fields": {"price": 10}}
  ],
  "patches": []
}
```

`record`는 기존 테이블의 0부터 시작하는 ID입니다. 원하는 항목의 ID는 **자신의 개인
캐시**에 있는 `data/port_ready/tables/item.dat.json`의 `records`에서 확인합니다.
확인한 전체 JSON이나 DAT를 모드에 넣지 말고, 위처럼 필요한 값만 변경하세요.

저장소의 [`example_item_price`](../mods/example_item_price/)를 복사해서 시작해도 됩니다.
이미 제공된 [`example_balance`](../mods/example_balance/)는 가격과 기존 스킬 MP를 함께 바꾸는 예제입니다.

## 2. 켜고 확인하기

1. 먼저 정품 폴더로 게임 준비를 끝냅니다.
2. 게임을 닫고 `Game-Setup-Windows.cmd` 또는 `Game-Setup-Mac.command`를 엽니다.
3. 추가 옵션의 **커스텀 모드 폴더** 목록에 자신이 만든 폴더 경로를 한 줄 넣습니다.
4. **연결하고 실행**을 누릅니다.

`mod.json` 파일 자체가 아니라 그 파일이 들어 있는 폴더를 지정합니다.
배포된 예제라면 `mods/example_item_price` 폴더가 대상입니다.
끄려면 목록에서 해당 줄을 지우고 앱을 다시 시작합니다. 실행 도중 자동 갱신하지 않습니다.

## 3. 새 파일과 JSON 패치 연습하기

[`example_settings`](../mods/example_settings/)는 원작 자료 없이 만든 JSON을 추가한 뒤,
그 JSON에 `set`, `append`, `remove` 패치를 적용합니다.

```text
example_settings/
├─ mod.json
└─ files/
   └─ custom/
      └─ demo_settings.json
```

이 파일의 논리 경로는 `custom/demo_settings.json`입니다. `files/`는 모드 폴더의
구조이고, 논리 경로 문자열에는 넣지 않습니다.

이 예제는 **파일 추가와 패치 형식을 배우는 예제**입니다. `difficulty`라는 임의의
JSON 값을 만들었다고 실제 게임 난이도가 자동으로 바뀌지는 않습니다. 그 값을 사용할
엔진 기능이나 도구가 별도로 있어야 합니다.

## 여러 모드의 적용 순서

목록 위에서 아래 순서대로 적용하며 **뒤쪽 모드가 우선**합니다.

- 일반 파일은 마지막 모드의 같은 논리 경로 파일을 읽습니다.
- JSON은 기본 파일을 읽은 뒤, 각 모드의 전체 파일 교체와 그 모드의 패치를 순서대로 적용합니다.
- 테이블은 각 모드의 전체 바이너리 교체가 있으면 먼저 적용하고, 그 모드의 `table_edits`를 적용합니다.
- 모드의 `id`는 서로 달라야 합니다. 같은 `id`를 두 번 넣으면 연결을 거부합니다.

뒤쪽 모드가 JSON 전체를 교체하면 앞쪽 패치 결과도 그 파일로 대체됩니다.
패치 대상은 기본 캐시, 앞선 모드 또는 자기 `files/`에서 그 시점에 존재해야 합니다.
더 뒤쪽 모드가 나중에 만들 파일을 미리 패치하는 방식은 사용할 수 없습니다.

## 세이브가 분리되는 이유

콘텐츠 ID와 활성 모드의 순서, `mod.json` 내용, 모드 파일 해시를 바탕으로 프로필을
구분합니다. 기본 게임과 다른 모드 조합은 같은 세이브 폴더에 저장하지 않습니다.

값을 바꾸거나 `files/` 아래 파일을 고치면 다른 프로필이 될 수 있습니다. `mod.json`의 버전·이름·
공백 같은 내용만 바뀌어도 파일 해시는 달라집니다. 제작 중에는 모드 원본과 자신의 세이브를
별도로 보관하고, 서로 다른 프로필의 세이브를 무조건 호환된다고 가정하지 마세요.

## v1과 v2의 지원 범위

- `schema: 1`의 데이터 파일 추가/교체, JSON 패치, 기존 item/magic/race 레코드 편집을 유지합니다.
- `schema: 2`의 새 캐릭터·매개변수 스킬·새 격자 맵·자작 스토리는 제작 GUI에서 작성할 수 있습니다.
- `table_edits`는 실제 규칙용 바이너리와 UI용 레코드를 함께 갱신합니다.
- 임의 GDScript·DLL·네이티브 모드 코드를 실행하는 플러그인 규격은 아닙니다.
- 기존 레코드 범위 밖의 ID는 `table_edits`가 아니라 v2 레지스트리에서 할당합니다.
- 새 스킬은 기존 처리·연출에 기반한 이름·MP·위력·거리 정의입니다. 임의의 새 동작 코드는 제작하지 않습니다.
- PNG/BMP를 넣는 것만으로 새 APD 애니메이션을 가져오거나 만들지는 않습니다.
- 새 대사에 사용할 글자가 기본 개인 글꼴 캐시에 없을 수 있습니다. CP949 전체 준비 옵션이나
  자신이 제공할 수 있는 글꼴/마스크 구성을 확인해야 합니다.

정확한 필드·자료형·논리 경로는 [FORMATS.md](FORMATS.md), 공개할 수 있는 자료의
경계는 [ASSET_POLICY.md](ASSET_POLICY.md)를 참고하세요.

## 현재 v2 기능과 남은 한계

| 만들고 싶은 것 | 현재 v2 | 남은 범위 |
| --- | --- | --- |
| 나만의 이야기 | 대사·변수·조건 분기·전투·종료 노드 작성/검사/실행 | 원작 특정 챕터에 삽입하고 다시 돌아오는 연결은 미지원 |
| 새 맵 | 기반 맵의 로컬 타일로 새 크기의 1-based 격자, 높이·지형·캐릭터 배치 | 자작 타일 가져오기와 세밀한 타일 그림 선택 도구는 미지원 |
| 새 캐릭터 | 원작 범위 뒤 새 ID, UTF-8 이름·레벨·능력치·스킬, 기존 CHAR 그래픽 참조 | 새 PNG/APD 제작·가져오기 미지원. 전투 간 육성 상태 자동 승계 미지원 |
| 새 스킬 | 새 ID·이름·MP·위력·거리와 기존 연출 선택 | 임의 엔진 동작·새 이펙트 스크립트 작성은 미지원 |

새 정의는 `pack_id:local_id`로 등록하며 같은 활성 정의 집합에서는 숫자 ID를 결정적으로
할당합니다. 내부 숫자 ID를 직접 고정해서 배포하지 마세요. 추가 필드·명령은 문서와
실제 검증기가 지원하는 범위만 사용할 수 있습니다. 확장팩을 테스트할 때는 원작 폴더를
선택하고 개인 캐시를 준비한 뒤 **저장하고 테스트**를 누릅니다.

원작 자원을 활용하는 제작 도구는 사용자의 로컬 정품 자원과 자작 자원을 구분해서
참조하고, 배포 모드에는 자작 콘텐츠와 필요한 변경 설정만 담는 방향으로 설계할 수 있습니다.
다만 정품을 보유했다는 사실이 수정·공개·재배포 전권을 주거나, 참조/레시피 방식이
제공자의 책임을 자동으로 없애 준다는 뜻은 아닙니다.
